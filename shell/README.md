# Flux shell

The desktop shell of Flux: the bar, the notification sidebar, the launcher and
the exit menu, plus the installer. Rust, GTK 4 and gtk4-layer-shell, styled with
the muse palette, running under niri.

## Programs

| Crate | Binary | What it does |
| --- | --- | --- |
| `statusbar` | `statusbar` | One bar per monitor: that output's niri workspaces, the focused window title, the date and time (click opens the sidebar), CPU and memory, the keyboard layout when there are several, and pills for volume, brightness, battery, network and the session menu |
| `sidebar` | `sidebar`, `flux-wallpaper` | The `org.freedesktop.Notifications` daemon: toasts in the top-right, a history panel, the light and dark toggle and the wallpaper picker |
| `launcher` | `launcher` | The application palette over every `.desktop` entry in `$XDG_DATA_DIRS` |
| `exit` | `exit` | The session menu: lock, suspend, log out, restart, power off |
| `installer` | `flux-installer` | The graphical installer on the live ISO |
| `shell-common` | (library) | Layer windows, the palette and scheme, shared CSS and motion, locale, single-instance and spawn helpers |

Every binary answers `--version` before it opens a display.

## How it runs on Flux

`modules/desktop-shell.nix` starts `statusbar`, `sidebar` and the wallpaper as
systemd user units bound to `graphical-session.target`. The units get
`/run/current-system/sw/bin` on their `PATH`, because NixOS writes a minimal
`PATH` into every user unit.

`modules/niri.kdl` binds the rest:

| Keys | Action |
| --- | --- |
| `Mod+Space` | `launcher` |
| `Mod+N` | `sidebar toggle` |
| `Mod+Escape` | `exit` |
| `Mod+Comma` | `flux-settings` |
| `Super+Alt+L` | `flux-lock` |

The statusbar reads niri through `$NIRI_SOCKET` directly. The sidebar and the
statusbar each keep one copy per session through a pid file in
`$XDG_RUNTIME_DIR` (`flux-<name>.pid`); `sidebar toggle` signals the running
daemon with `SIGUSR1`.

## Files

| Path | What |
| --- | --- |
| `/etc/flux/palette-light.css`, `palette-dark.css` | the muse palette, generated by `pkgs/flux-theme` |
| `~/.config/flux/palette.css` | optional overrides of any `@fc_*` colour |
| `~/.config/flux/<widget>.css` | optional replacement of a widget's stylesheet, reloaded live |
| `~/.config/flux/wallpaper` | the chosen wallpaper, one path |
| `~/.local/state/flux/notifications.json` | the notification history, 50 entries |

The light or dark scheme comes from `org.gnome.desktop.interface color-scheme`,
which `flux-scheme` writes; without that schema the XDG desktop portal answers.

## Look and motion

Colours only through `@fc_*`, no borders, Inter, 12 px radius on surfaces and
8 px on controls. Buttons ease their fill on hover and press; the panels slide
and fade in over 160 ms. With `gtk-enable-animations` off, all of it is instant.

Strings exist in English and French; the language follows `LC_ALL`,
`LC_MESSAGES` or `LANG`.

## Develop

From the repository root:

```sh
scripts/dev.sh cargo check --workspace
scripts/dev.sh cargo test --workspace
scripts/dev.sh cargo clippy --workspace -- -D warnings
```

`scripts/dev.sh` runs cargo inside the Flux dev shell in Docker. GTK checks
that need a display stand down when there is none.

`FLUX_SHELL_PREVIEW=1` opens `exit` with every choice disarmed and fills the
sidebar with sample notifications, for screenshots.

`statusbar --diagnose` prints which pills answer and why, and whether the
glyphs paint.
